# 관리자 workspace 기능 인벤토리

기준: `admin.html`, `js/admin*.js`, `css/admin.css`, `server.js`의 관리자 API.

목표는 기존 화면을 복제하는 것이 아니라 실제 업무를 기준으로 기능을 유지·개선·통합·폐기하는 것이다. 이 문서의 `확정` 항목은 코드상 호출 관계와 중복이 명백한 경우이며, 운영 판단이 필요한 항목은 `결정 필요`로 남긴다.

## 제안 정보 구조

| 영역 | 포함 업무 |
|---|---|
| 홈 | 미확인 상담, 오늘 운영 현황, 즉시 처리할 항목 |
| 상담 | 진행 중·저장 상담 통합 목록, 상세, 검색, 메모, 첨부, 난입·복귀, 답장 |
| 견적 | 견적 목록, 검색·필터, 상세 편집, 상담에서 견적 등록, 출력·내보내기 |
| 분석 | 방문·전환·유입 소스, 상담 추이, AI 비용·토큰 |
| 데이터 관리 | 휴지통 복원·영구삭제, 백업·내보내기 |

메인 사이트와 고객 채팅 미리보기는 업무 영역이 아니므로 사이드 메뉴에서 제거하고 헤더의 외부 링크로 이동한다. 서버 상태, 알림, 새로고침, 로그아웃은 헤더에 둔다.

| 대시보드 상담 카드 목록 | 통합 확정 | `dashboardSessionList`와 대화 탭이 동일한 진행/저장 상담을 각각 렌더링하고 별도 폴링한다. 홈에는 요약과 이동 링크만 남긴다. | 상담 |

| 대시보드 유입 소스 | 통합 확정 | 방문자 통계의 유입 소스 성과 표와 중복된다. 홈에는 필요 시 오늘 요약만 남기고 상세는 분석으로 통합한다. | 분석 |

| 견적 Excel·인쇄 | 유지 | 운영 출력 기능이다. 목록 필터 결과와 상세 견적 출력의 범위를 명확히 구분한다. | 견적 작업 메뉴 |
| 진행 중 상담 목록 | 유지/개선 | 핵심 업무다. 저장 상담과 한 목록 모델로 통합하고 상태 필터로 구분한다. | 상담 |
| 저장 상담 목록·상세 모달 | 통합 확정 | 라이브 탭에서도 저장 상담을 합쳐 표시하고 별도 `section-history`와 상세 모달이 다시 존재한다. 하나의 상담 workspace 상세 패널로 통합한다. | 상담 |
| 상담 난입·AI 복귀·답장 | 유지/개선 | 핵심 완료 업무다. mutation 진행 중 상태와 실패 복구를 제공하고 선택 상담 변경 시 오발송을 막는다. | 상담 상세 |
| 상담 메시지 검색 | 유지/개선 | 긴 대화 탐색에 필요하다. 검색 UI와 결과 이동 상태를 상세 header에 고정한다. | 상담 상세 |
| 답장 인용·컨텍스트 메뉴 | 개선 | 기능은 유용하지만 우클릭 중심이고 모바일 경로가 불명확하다. 메시지 action 메뉴로 통합한다. | 메시지 action |
| 파일 첨부·붙여넣기·미리보기 | 유지/개선 | 핵심 응대 기능이다. 업로드 진행률, 취소, 실패 재시도와 모바일 picker를 동일 흐름으로 만든다. | 답장 composer |
| 상담 정보 자동 요약·개략 견적 | 결정 필요 | 실제 상담 판단에 쓰이는지, 추정 가격이 오해를 만드는지 운영 확인이 필요하다. 유지 시 "참고용" 출처와 계산 근거를 노출한다. | 상담 보조 패널 |

| 같은 손님 관련 세션 | 유지/개선 | 재방문 맥락에 유용하다. 별도 임시 모달보다 상담 상세의 관련 상담 영역으로 이동한다. | 상담 상세 |

| 브라우저·인앱 알림 | 통합/결정 필요 | 알림, NEW badge, seen count가 여러 구현으로 중복된다. 인앱 activity 상태를 정본으로 만들고 데스크톱 알림 유지 여부만 결정한다. | 헤더 알림 |
| 방문자 통계 | 유지/통합 | KPI, 전환, 시간대, 소스 성과는 유용하지만 대시보드·상담 통계와 중복된다. 하나의 분석 영역으로 합친다. | 분석 |

| 휴지통 복원·영구삭제 | 유지/개선 | 데이터 복구에 필요하다. 영구삭제는 대상 요약, 복구 불가, 결과를 보여주는 확인 Dialog로 교체한다. | 데이터 관리 |
| 전체/테이블 백업 | 유지/개선 | 운영 안전 기능이다. 최상위 메뉴 대신 데이터 관리로 이동하고 마지막 백업 시각을 브라우저가 아닌 서버 기준으로 전환할지 별도 결정한다. | 데이터 관리 |
| 채팅 상담·메인 사이트 링크 | 위치 변경 확정 | 앱 내부 업무 화면이 아니다. 사이드 메뉴에서 제거한다. | 헤더 외부 링크 |
| 도움말 tour 모달 | 폐기/대체 확정 | 현재 탭별 설명을 하드코딩해 화면 변경 시 즉시 낡는다. 정적 tour는 제거하고 필요한 곳에 짧은 문맥 도움말을 둔다. | 각 작업의 help text |
| 오프라인 `loadDemoData()` | 폐기 확정 | 서버 연결 실패 시 실제 관리자 목록에 샘플 견적을 주입해 운영 데이터처럼 보이게 한다. 오류/재시도 상태로 교체한다. | 제거 |
| `saveConversationManual()` 클라이언트 함수 | 폐기 후보 확정 | 정의와 API 호출은 있으나 호출처가 없다. 자동 저장·난입 persistence와도 책임이 겹친다. 서버 endpoint의 외부 사용 여부 확인 후 함께 제거한다. | 제거 |
| 중복 사이드바 + 전체 탭 바 | 폐기/재구성 확정 | 동일 업무 이동을 두 UI가 반복하고 숨겨진 탭까지 섞는다. 사이드 메뉴는 영역, 본문 탭은 해당 영역의 세부 보기만 담당한다. | workspace shell |

## 현재 구조의 주요 동작 결함

1. 라이브 목록, 선택 메시지, 대시보드 상담, 저장 상담, 세션 확인, 서버 확인이 각각 타이머를 소유한다.
2. 진행 상담과 저장 상담을 여러 renderer와 상세 UI가 중복 처리한다.
3. 모달들이 body scroll lock, 내부 scroll boundary, 최상위 focus/stack 계약을 공유하지 않는다.
4. 탭 전환이 DOM 표시와 전역 변수에 결합돼 선택·검색·작성 상태의 수명이 불명확하다.
5. 모바일 기능 상당수가 데스크톱 DOM을 CSS로 재배치하는 방식이라 목록/상세/키보드 전환 상태가 명시적이지 않다.
6. 문자열 HTML 조립, inline handler, `window.*` 함수가 기능 간 의존성을 숨긴다.

## 첫 구현 단위

첫 PR은 기능 하나만 떼어낸 축소 화면이 아니라 다음 뼈대를 만든다.

1. 홈·상담·견적·분석·데이터 관리의 workspace shell
2. 헤더 전역 상태와 외부 링크
3. 영역/세부 탭의 역할 분리와 route state
4. 공통 modal scroll lock 및 내부 scroll container
5. 기존 기능을 아직 React로 옮기지 않은 영역에는 기능 목록과 이관 상태를 표시하되, 기존 `/admin`으로 명시적으로 돌아갈 수 있게 한다.
6. 첫 실제 업무로 상담 통합 목록과 상세 읽기를 연결하고, 난입·답장·첨부 등은 parity 묶음으로 순차 연결한다.

## 삭제 전 확인 항목

- 빠른 답변 템플릿을 실제로 사용하는가?
- 상담 정보 자동 요약과 개략 견적을 상담원이 실제 판단에 사용하는가?
- 브라우저 데스크톱 알림이 필요한가, 인앱 알림만으로 충분한가?
- 테이블별 CSV가 필요한가, 전체 ZIP만으로 충분한가?
- `/api/admin/save-conversation`을 브라우저 밖에서 호출하는 운영 도구가 있는가?

위 다섯 항목 외에는 이 문서의 통합·폐기 결정을 첫 구현 기준으로 사용한다.
